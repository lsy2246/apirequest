# 单机抓包

抓包页面只管理运行抓包程序的这台机器。提供系统代理和本机透明捕获，单次只运行一个入口。
WireGuard、多设备登记、接入账号、二维码、设备选择和按设备匹配规则已移除，不提供旧接入 API 适配。
历史会话仍保存在原来的 `sessions/` 目录，不删除正文或根证书。

## 操作与生命周期

- 进入页面只启动控制进程，不开始捕获或改系统代理。点击「开始记录」才开启本机入口。
- 系统代理监听 `127.0.0.1:18888`，自动识别 HTTP CONNECT 和 SOCKS5，不对局域网或公网开放。
- macOS、Windows 可以自动配置系统代理；透明捕获依赖本机系统授权。已有代理配置仍拒绝覆盖。
- 「暂停记录」停止新请求入档，保留网络转发和已应用规则；恢复使用同一归档。暂停不新增不可操作的断点。
- 会话面板可新建和重命名；尚未结束的请求继续写入原会话，完成后才关闭归档。活动会话不能删除。
- 捕获模式变更前需暂停；保存时关闭旧入口并恢复本应用持有的系统代理。退出时回收连接、重放和监听。
- 捕获设置管理本机根证书，信任操作需单独确认。公网管理页面只提供证书下载，不远程更改系统信任。

## 实现

`controller.py` 持有一个 `CaptureRuntime`、当前归档和仍有在途请求的旧归档。
`capture_modes.py` 只接受 `system` / `local`；`capture_context.py` 仅传递本机进程元数据。
`archive_api.py` 统一实时和历史查询；`session.py` 执行规则、断点和原样重放。
配置写入私有 `capture.json`，规则和设置使用修订号防止并发覆盖，不自动恢复捕获。

网页和桌面分别通过 Node 控制服务和 Rust IPC 管理同一引擎。前端统一调用 `capture_api`，
请求体只有 `action` 和 `input`，不携带设备 ID。原多设备配置不再加载；历史归档无需迁移。
网页的 Host、Origin、专用请求头检查及生产管理身份验证保留。

## 配置与部署

调试版配置 `APIREQUEST_CAPTURE_EXECUTABLE` 和 `APIREQUEST_CAPTURE_CA_DIR`。
独立控制服务继续使用 `APIREQUEST_CAPTURE_ORIGIN`、`APIREQUEST_CAPTURE_OWNER_SECRET_FILE`、
`APIREQUEST_CAPTURE_EXECUTABLE` 和 `APIREQUEST_CAPTURE_CA_DIR`；管理接口经同源 HTTPS 反向代理。
不再分配设备端口或发布 UDP。普通容器只能捕获容器自己的流量，不能因此捕获宿主机。

## 验证入口

- `python3 -m unittest discover -s capture/tests -p 'test_*.py'`：入口、进程元数据、系统代理与归档回归。
- `python3 capture/tests/smoke_single.py --executable /path/to/mitmdump`：隔离的真实单机代理，临时目录和端口，系统代理关闭。
- 构建 `capture/server.vite.config.ts` 后运行 `capture/tests/server.test.mjs`、`capture/tests/server.integration.mjs`：管理口与生产控制协议。
- 桌面 `capture::tests`：随包引擎的真实 HTTP 转发和归档，测试独占随机端口，不修改系统设置。

历史开发和验证记录保留在 [HISTORY.md](HISTORY.md)，只代表对应日期版本。

## 页面实时更新

管理服务通过 `GET /__workbench_capture/events` 提供 SSE 变化通知，沿用管理口的所有者认证、
来源校验和 `X-Workbench-Capture` 请求头；桌面通过 `workbench-event` IPC 使用同一事件协议。
归档摘要和正文写入完成后通知宿主，事件只携带变化标记，正文继续按需分页读取。
前端统一合并变化通知并重新读取受影响的数据，空闲时不再定时查询状态、列表或详情。

页面实时更新始终开启，连接状态统一显示在导航栏底部；抓包记录仍通过开始和暂停记录按钮控制。
页面切到后台后继续同步，重新连接时读取完整快照补齐变化，无需用户配置。
每个宿主共享连接，断开时清理订阅；SSE 心跳不触发业务查询，慢连接通过重连和快照恢复。
