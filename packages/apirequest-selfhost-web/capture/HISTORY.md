# 抓包历史开发与验证记录

以下是各历史版本的原始记录，已移除能力不代表当前产品支持。当前使用方式以 [README](README.md) 为准。

# 抓包服务

调试版和桌面版使用同一套 mitmproxy 插件。调试版通过 Vite 的本地中间件管理引擎，
桌面版通过 Rust IPC 管理随包提供的引擎。流量由代理引擎转发，工作台接收有界的预览、
状态和正文预览。原始请求头、地址与正文保存在本地磁盘，关闭引擎只释放监听端口
和执行中的临时数据，归档继续保留。

## 调试配置

在 selfhost-web 开发环境配置中填写本机 mitmdump 可执行文件及独立 CA 目录。
只填写可执行文件，无需安装系统 Python 包。

~~~dotenv
APIREQUEST_CAPTURE_EXECUTABLE=/path/to/mitmdump
APIREQUEST_CAPTURE_CA_DIR=/path/to/private-capture-ca
~~~

本地管理 API 仅接受工作台的回环请求，校验 Host、Origin 及专用标头。
默认仅监听 127.0.0.1，点击开始即可接收客户端发送到代理的流量，无需填写目标或选择模式。
同一个 18888 端口自动识别 HTTP（包含 HTTPS CONNECT）与 SOCKS5，工作台自身端口不可抓取。
顶部开始/停止统一本机系统代理的启用与恢复，默认自动选择当前网络服务。可以在代理与
证书面板预先指定服务；证书管理在停止状态也可使用。

局域网模式只允许绑定私有 IPv4 地址，并要求指定唯一测试设备 IP。移动设备需手动
设置 HTTP 代理并信任下载的 CA。系统代理使用绕过工作台与自身监听端口的通用 PAC，已有 PAC 或手动
代理时拒绝覆盖。系统设置更改依赖操作系统权限。证书信任须单独确认，停止抓包会恢复
本次启用的代理，证书由用户显式移除。恢复失败时保留快照，供后续恢复重试。

## 会话和规则

抓包设置中的 15 项限额及配置定义已经删除，不保留隐藏的用户配额。

- 实时和历史列表均从磁盘分页读取，没有近期记录条数上限。
- 请求和响应头完整保留，不按数量或字符数截断，包含认证信息及 Cookie。原始地址
  的查询参数完整保留；本地详情、转为接口及 HAR 使用同一份原始记录。
- HTTP 正文始终流式写盘，不提供单独的存储开关，WebSocket 文本和二进制消息也完整归档；正文可能包含
  业务秘密，应按分享范围选择导出。详情分块阅读，完整文件可以下载。
- HAR 文件导入已移除。导出从磁盘串流读取，不把整个会话装入内存。
- 重放从磁盘读取完整记录，不再提供缓存或开启开关。批量重放逐条读取正文、执行并
  释放，发送时复用锁定版本代理引擎的连接与 TLS 实现。引擎重新启动后可以重放旧
  会话的完整请求，仍阻止访问工作台与代理自身；旧版已经去掉的认证头无法自动补回。
- 内存保护只管理正文预览。归档逐块直接写盘，没有待写盘队列、积压预算
  或队列满丢弃机制；磁盘较慢时会拖慢代理转发，实际写盘失败仍显示归档不完整。
- 会话保存在宿主数据目录；旧 IndexedDB 会话在打开会话面板时迁入磁盘，成功后才移除。
- 请求和响应断点在标头阶段暂停，120 秒后自动继续。可以补丁方式编辑普通标头、
  同源请求 URL 或响应状态。认证头、Cookie 和影响消息分帧的标头不开放编辑。
  清空列表会释放当前断点。
- 规则 JSON 为数组，支持 action、match、method。match 按 URL 片段匹配，
  method 可留空。action 为 pause_request、pause_response、rewrite、local 或 network。
  同类规则取第一个匹配项。rewrite 的 value 必须同源。local 可设置 status、
  contentType 和 value。network 的 delayMs 为 0–10000，loss 为 0–100，
  表示请求失败概率。
- 同一入口自动识别 HTTP 与 SOCKS5，HTTPS 使用 CONNECT 后解密；不提供 HTTP/3 反向代理。
  WebSocket 消息不进入 HTTP 原样重放。证书固定和未信任 CA 的客户端需要测试配置配合。

## 移除待写盘队列（2026-11-11）

用户要求移除待写盘数据的内存保护。本次删除归档队列、队列内存预算、后台写入线程、
队列溢出丢弃逻辑及 `pendingBytes` 状态字段。正文块、消息和元数据在归档调用中直接
写入文件，没有用无界队列替代原来的有界队列。磁盘较慢会拖慢代理转发；实际磁盘错误
仍计入归档不完整，后续块继续尝试写入。关闭归档无需排队收尾，只更新未完成请求状态。
这是应用层写入方式变更，不承诺断电后的物理持久性。

预览及原样重放的内存管理不变。重放缓存暂存请求原始正文及认证信息，用来再次发送

## 2026-11-11：系统代理、本机透明捕获与 WireGuard

用户选定三种捕获方式，顶部通过同一模式选择器切换，一次只运行一个入口。模式使用

- 系统代理沿用 HTTP/HTTPS 与 SOCKS5 共端口 18888。顶部开始/停止自动管理系统代理；

## 2026-11-11：服务端与多设备管理

本节替代上述「一次只运行一个入口」「WireGuard 只提供一个客户端」「仅开发环境有网页
管理接口」的现行说明。旧记录保留为其当时版本的验证证据。

### 使用方式

抓包页的「管理设备」支持添加代理设备、WireGuard 设备及引擎本机捕获；多个入口可同时
运行。代理设备使用独立用户名和密码，HTTP CONNECT 与 SOCKS5 认证均在接入端校验，
凭据不会转发给上游或写入流量归档。WireGuard 每台设备独立密钥和 UDP 端口，可下载
配置或在浏览器内生成二维码；二维码、配置和密码只在显式打开连接配置时显示。

设备列表展示启用状态、近期活动、当前会话请求数和连接地址；空闲表示尚无近期请求，
不以此判定设备已物理离线。顶部可选择全部设备或指定设备，流量摘要保存设备 ID、名称
快照和真实会话 ID，同一 NAT 出口或相同 WireGuard 内层 IP 均不会混淆设备身份。

「暂停记录」停止新请求入档，保留转发及已启用的网络/响应/改写规则，不再新增无法在列表操作的断点。「新建会话」按设备创建新的归档，
已有长连接仍写入原会话，直到完成后收尾。禁用设备明确断开其连接，其他设备继续工作。
禁用、删除和重置凭证均需在界面确认；删除设备保留历史会话，历史需单独清理。
规则可限定设备，空选择适用于全部设备。每种操作采用首条匹配规则；请求阶段按断点、
网络模拟、本地响应、同源改写执行，响应阶段处理响应断点。配置在应用后持久保存。

代理或 WireGuard 只是流量入口；HTTPS 解密仍需要在被抓设备信任本服务的 CA。连接
配置提供平台说明、公开证书下载、实际流量检查及 HTTPS 解密反馈。引擎本机的证书信任
仍是单独确认的操作。服务器部署不会通过网页修改访问者电脑的系统代理或证书。

### 运行与存储契约

- `devices.py` 负责设备登记、凭证、端口分配、配置修订号及监听生命周期；`device_context.py`
  在已验证的连接任务上传递身份，不信任业务请求头中的设备标记。
- `capture_modes.py` 保留原生协议适配，增加设备上下文和本次连接任务的回收。
  `recorder.py` 为每条流量固定归档引用，`archive_api.py` 共用跨设备查询及活动归档保护。
  `replay.py` 隔离锁定版本的单请求重放处理器，避免常驻全局重放队列丢失设备上下文，取消时只回收本次处理器的连接。
- `service.ts` 提供不依赖 Vite 的进程管理与文件接口，开发插件只保留回环校验。
  网页开发插件、正式 Node 控制服务和 Rust 桌面宿主均调用 `workspace_api` 引擎命令。
  正式网页管理不再依赖 Vite 的 `configureServer`。已有单入口底层命令仅用于宿主及定向
  回归，不再作为抓包页面的另一套操作入口。
- 私有配置根目录保存 `devices.json`、设备密钥和 `sessions/`。配置文件用 0600 权限
  原子替换，CA 与设备配置目录必须放入持久卷。设备与规则修改校验修订号，过期编辑
  返回 `revision_conflict`，不会静默覆盖另一窗口。
- 会话与正文继续使用现有磁盘格式，不新增浏览器副本，也不设置归档总量或保留期限。
  列表流式扫描摘要，正文每次读取 64 KiB；归档写入失败通过 dropped 状态反馈。
  当前跨设备列表使用有界分页窗口，深页 offset 超过 100000 时需缩小设备/域名筛选或
  打开历史会话查看，不删除或截断已保存的数据。
- 管理页面使用定时增量刷新状态和当前页。尚未引入 WebSocket/SSE 控制订阅；网络断线
  不会改变设备监听或转发生命周期。

### 正式服务端部署

构建独立服务（只依赖 Node 内建模块；引擎使用 mitmproxy 12.3.0）：

~~~sh
cd packages/apirequest-selfhost-web
pnpm exec vite build --config capture/server.vite.config.ts
APIREQUEST_CAPTURE_SERVER_ENTRY=true node capture-dist/server.mjs
~~~

必须配置：

| 配置 | 含义 |
| --- | --- |
| `APIREQUEST_CAPTURE_ORIGIN` | 浏览器实际访问的工作台 HTTPS 源，包括非默认端口 |
| `APIREQUEST_CAPTURE_OWNER_SECRET_FILE` | 管理密钥文件，至少 24 字符；不提交到 Git |
| `APIREQUEST_CAPTURE_CA_DIR` | 私有、可写、持久化的配置与流量目录 |
| `APIREQUEST_CAPTURE_PUBLIC_HOST` | 设备可以访问的服务器域名或地址 |
| `APIREQUEST_CAPTURE_EXECUTABLE` | mitmdump 路径；容器内默认使用 PATH |
| `APIREQUEST_CAPTURE_CONTROL_BIND` / `CONTROL_PORT` | 管理监听，默认 127.0.0.1:3190 |
| `APIREQUEST_CAPTURE_DEVICE_BIND` | 手工代理入口监听地址，服务端默认 0.0.0.0 |
| `APIREQUEST_CAPTURE_PROXY_PORTS` | 代理端口范围，默认 18900-18999 |
| `APIREQUEST_CAPTURE_WIREGUARD_PORTS` | WireGuard UDP 端口范围，默认 51820-51919 |
| `APIREQUEST_CAPTURE_ALLOW_PRIVATE_TARGETS` | 明确允许服务器访问内网目标，默认 false |

上表 `CONTROL_PORT` 的完整变量名为 `APIREQUEST_CAPTURE_CONTROL_PORT`。
也可通过 `APIREQUEST_CAPTURE_OWNER_SECRET` 注入管理密钥，推荐使用密钥文件。
前端构建时设置 `VITE_WORKBENCH_CAPTURE=true`，把 `nginx.example.conf` 的管理路由加入
现有工作台 HTTPS server，保持原始 Host 与 Origin，避免 SPA 回退吞掉 API 路由。
`compose.example.yml` 和 `Dockerfile` 提供独立抓包服务；默认只发布 WireGuard UDP，
管理端口绑定回环，HTTP/SOCKS5 入口不发布到公网。需要代理接入时仅绑定可信网卡并
限制防火墙来源，不能把明文代理认证当作加密传输。持久卷需允许容器 UID 10001 写入。

公网控制入口使用管理员解锁、随机会话和 HttpOnly/SameSite Cookie；HTTPS 部署使用
Secure Cookie。服务端校验 Host、Origin 和专用标头，限制登录尝试，轮换登录会话，
登出撤销令牌，执行 24 小时空闲与 7 天绝对过期。服务重启后需要重新解锁，设备接入
配置不变。默认禁止访问非公网目标与管理服务回环；显式允许内网也保留自身监听保护。
密钥不写日志，设备凭证不放状态轮询结果，CA 私钥不提供下载。

服务端本机捕获受宿主平台和权限限制；普通非特权容器不能因此捕获宿主所有进程。
WireGuard 默认接管 IPv4，IPv6 流量不承诺完整捕获。目标从抓包服务器访问，客户端的
localhost 和私网服务需额外网络连接。证书固定或拒绝用户 CA 的应用需单独测试配置。

关闭服务时正常发送 SIGTERM，等待引擎恢复其持有的系统代理、放行断点并关闭本次监听；
保留持久卷。功能关闭与删除设备不会移除客户端已经安装的 CA，客户端应主动关闭代理/
WireGuard 并按需要移除信任。回退界面前先停止多设备服务，避免旧界面无法管理活动设备。

## 私有测试 CA 的上游信任配置（2026-11-12）

浏览器信任抓包 CA，与抓包引擎信任目标服务器 CA 是两件事。测试站使用内部 CA 时，
即使浏览器已经信任抓包 CA，引擎仍可能因 `Certificate verify failed` 返回 502。
本次在当前调试实例的数据目录配置 `config.yaml`，通过引擎原生选项
`ssl_verify_upstream_trusted_ca` 使用合并后的 PEM 信任库：保留本版引擎 certifi 的
公共根证书，追加经测试服务器既有 SSH 主机身份取回、并核对目标证书链的测试 CA。
没有关闭证书校验，没有导入 CA 私钥，也没有修改系统或浏览器的信任设置。

配置和 CA 公共证书保存在应用的本机数据目录，不放入 Git，不改变其他部署实例。
引擎更新 certifi 根证书后，须用新版公共根证书重新生成该合并文件。移除测试 CA 时
从合并库删除该证书，或移除该选项恢复内置公共 CA，再重启抓包引擎。

实际验证：独立临时代理复现默认配置访问测试首页为 502；追加测试 CA 后为 200，
普通公开 HTTPS 首页也为 200。随后通过当前调试页面使用的真实引擎再次代理访问
测试首页，返回 200；只请求公开首页，不执行登录或客户业务操作。验证所用临时
代理设备已删除，监听端口已关闭，原有设备开关、暂停状态和会话集合保持不变。
本次为环境信任配置修复，没有修改测试服务器证书或服务，也没有提交或推送 Git。
